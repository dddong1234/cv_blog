핵심 Takeaway

지표는 단순히 "좋다/나쁘다"를 알려주는 게 아니다. Train과 Test를 비교해야 모델 상태를 진단할 수 있고, 상태에 맞는 전략을 고를 수 있다.

회귀 평가지표 완전 정리
각 지표가 무엇에 민감한지를 이해하면, 지표 조합으로 모델 문제를 진단할 수 있다.
지표공식민감한 것언제 사용단점
RSS Σ(yᵢ - ŷᵢ)² 이상치, 데이터 수 내부 최적화 기준 데이터 수에 비례 → 비교 불가
MSE RSS / n 큰 오류 (제곱) 이상치가 치명적일 때 단위² → 해석 어려움
RMSE √MSE 큰 오류 (가장 강함) 이상치 존재 파악 이상치에 과민 반응
MAE Σ|yᵢ - ŷᵢ| / n 균등한 오류 이상치 영향 줄일 때 미분 불연속 (0에서)
MAPE Σ|e/y| / n × 100% 상대적 오류 스케일 다른 비교 y≈0이면 폭발, 비대칭
RMSLE √Σ(log(ŷ+1)-log(y+1))²/n 비율 오류 (로그) 가격/주가 등 지수 분포 과소예측을 더 엄하게 처벌

RMSE vs MAE — 이상치 민감도 비교
이상치가 있을 때 RMSE는 오류를 제곱하여 크게 반응, MAE는 선형적으로 반응. RMSE≫MAE면 이상치 존재 신호.
핵심 Takeaway

RMSE와 MAE를 함께 보자. 두 값의 차이 자체가 이상치 여부를 알려주는 신호다. R²는 절대적 오류 크기를 말하지 않으니 RMSE와 함께 해석해야 한다.

Accuracy 전체 정확도
(TP + TN) / (TP + FP + FN + TN)
전체 예측 중 맞은 비율. 클래스 불균형 시 위험. 암 진단에서 99% 음성이면 항상 음성이라 해도 99% 정확도.
Precision 정밀도
TP / (TP + FP)
양성이라 예측한 것 중 진짜 양성 비율. FP를 줄이는 것이 목표일 때 중요. (스팸 필터, 법정 증거)
Recall (Sensitivity) 재현율
TP / (TP + FN)
실제 양성 중 잡아낸 비율. FN을 줄이는 것이 목표일 때 중요. (암 진단, 사기 탐지)
F1-Score 조화평균
2 × (Precision × Recall) / (Precision + Recall)
Precision과 Recall의 균형. 둘 다 중요할 때 사용. 하나가 0이면 F1도 0이 된다.
실제 사례별 중요 지표
사례더 중요한 지표이유FP vs FN 비용
🏥 암 진단 Recall ↑ 암을 놓치면(FN) 치명적 FN 비용 >> FP 비용
📧 스팸 필터 Precision ↑ 정상 메일을 스팸으로 분류(FP)가 더 나쁨 FP 비용 > FN 비용
💳 사기 탐지 Recall ↑ 사기를 놓치면(FN) 금전적 피해 FN 비용 >> FP 비용
🎯 추천 시스템 F1 균형 관련 없는 추천(FP)과 놓친 추천(FN) 모두 중요 비슷한 비용
🔍 콘텐츠 검색 Precision ↑ 관련 없는 결과가 많으면(FP) 사용자 이탈 FP 비용 > FN 비용
핵심 Takeaway

Accuracy만 보지 마라. FP와 FN 중 어느 실수가 더 치명적인지를 먼저 결정하고, 그에 맞는 지표를 선택한다. 암 진단이라면 Recall이 낮은 모델은 아무리 Accuracy가 높아도 위험하다.

Trade-off를 그림으로 이해하기
머신러닝에는 피할 수 없는 균형이 존재한다. 한쪽을 올리면 다른 쪽이 내려간다. 이 균형점을 찾는 것이 모델 튜닝의 핵심이다.
1. Bias-Variance Trade-off
Underfitting (High Bias)
모델이 너무 단순. 데이터를 충분히 학습 못 함. Train/Test 둘 다 나쁨.
→ 모델 복잡화, 피처 추가
Good Fit
Train ≈ Test 성능. 새 데이터에도 잘 작동. 목표 상태.
→ 유지 또는 미세 조정
Overfitting (High Variance)
훈련 데이터를 외워버림. Train 좋음, Test 나쁨.
→ 정규화, 데이터 증가
2. Precision-Recall Trade-off (threshold 조절)
3. Regularization Trade-off (Ridge / Lasso)
정규화 없음 → Overfitting 위험
Ridge/Lasso → 일반화 향상
방법패널티효과언제
Ridge (L2)Σβ²계수를 0 근처로 축소 (제거는 안 함)모든 피처가 의미 있을 때
Lasso (L1)Σ|β|계수를 정확히 0으로 (피처 선택)불필요한 피처 제거 원할 때
핵심 Takeaway

Trade-off는 피할 수 없다. Precision을 올리면 Recall이 내려간다. 정규화를 강하게 하면 Bias가 올라간다. 도메인에서 어떤 실수가 더 비싼지를 먼저 결정하고, 그 방향으로 threshold를 조절한다.

Residual Plot 해석 가이드
잔차(Residual = 실제값 - 예측값)를 시각화하면 모델이 어디서, 어떻게 실패하는지 알 수 있다.
잔차 패턴의미원인권장 액션
랜덤 분포 모델이 잘 학습됨 - 유지 또는 하이퍼파라미터 미세조정
곡선 패턴 비선형 관계 포착 못 함 선형 모델의 한계 다항식 항 추가 / Tree 기반 모델로 교체
팬(깔때기) 모양 이분산성 (큰 값일수록 오류 큼) 분산이 균일하지 않음 타겟 로그 변환, WLS(가중 최소제곱)
계통적 편향 특정 방향 오류 지속 중요 피처 누락 도메인 지식으로 피처 추가
이상점 클러스터 특정 구간에서 실패 서브그룹 존재 구간별 모델 분리, 클러스터링 추가
핵심 Takeaway

숫자 지표만 보지 말고 Residual Plot을 반드시 그려라. RMSE가 좋아도 잔차에 패턴이 있으면 모델은 아직 개선 여지가 있다. 패턴 → 원인 → 액션 순서로 생각하면 된다.

CV 결과 해석 → 의사결정
CV Mean 좋음 + Std 낮음
예: RMSE = 0.85 ± 0.03
안정적인 모델. 어떤 데이터를 줘도 일관된 성능. 배포 준비 완료.
→ 하이퍼파라미터 최종 조정 후 배포
CV Mean 좋음 + Std 큼
예: RMSE = 0.85 ± 0.25
평균은 좋지만 불안정. 특정 데이터 분할에 의존적. 실서비스 위험.
→ 더 많은 데이터 / Stratified Fold / Ensemble
CV Mean 나쁨 + Std 낮음
예: RMSE = 3.20 ± 0.04
안정적으로 나쁨. 일관된 Underfitting 신호.
→ 모델 복잡화 / Feature Engineering
CV Mean 나쁨 + Std 큼
예: RMSE = 3.20 ± 1.50
최악. 모델도 나쁘고 불안정. 데이터나 파이프라인 문제일 수도.
→ 데이터 품질 확인부터 시작
핵심 Takeaway

CV Mean은 모델의 평균 실력, CV Std는 안정성이다. 둘 다 봐야 한다. Std가 크면 Mean이 아무리 좋아도 실서비스에서 갑자기 무너질 수 있다. 보통 Std ≤ 0.1 × Mean이면 안정적이라 판단한다.

최종 의사결정 플로우차트
지표를 봤다면, 이 흐름을 따라가면 된다. 각 단계마다 판단 기준과 액션이 연결되어 있다.
핵심 Takeaway

의사결정은 항상 이 순서다: Train/Test 비교 → Residual 패턴 → CV 안정성. 각 단계에서 문제가 발견되면 해당 전략을 적용하고 다시 처음으로 돌아간다. 이 루프가 실전 ML 엔지니어링의 핵심이다.

최종 Takeaway

지표는 암기하는 게 아니라 흐름으로 이해하는 것이다. 지표 조합을 보고 → 모델 상태를 추론하고 → 액션을 결정하는 사고 루프가 자동으로 돌아갈 때까지 반복하면 실전 ML 엔지니어가 된다.
